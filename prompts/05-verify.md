# 검증 요청 · 기대값과 실제 결과

notes/spec.md의 확정 규칙으로 검증해. 미확정 조건은 임의로 정답 처리하지 마.
반환 결과와 원자료에서 제약을 별도 로직으로 재계산하고 중복·누락·시간·정원 등 실제 요구의 위반 목록을 보여 줘. 생성 함수가 반환한 valid=true만 믿지 마.
작은 입력은 손계산 기대값 또는 가능한 범위의 완전 탐색과 비교해. 기준 해법보다 나음, 제약 충족, 전역 최적성은 별개로 보고해.
빈 입력·최솟값/경계값·잘못된 단위/ID·해를 못 찾는 조건·실제 최대 예상 규모를 위험에 맞춰 확인해. 처리시간과 실패 상태도 기록해.
UI·API 과제라면 핵심 흐름과 API 직접 호출로 권한·잘못된 입력·상태 전이·미확정 결과 노출을 확인해. 요구 변경 후 이전 후보 확정, 중복 확정·재시도, 재시작 후 유지가 필요한지도 요구에 맞춰 확인해.
실제 실행 명령·입력·기대값 근거·출력·판정·미실행을 notes/work.md에 요약하고 긴 결과는 verify/results/에 남겨. 영향 있는 변경 후 해당 검사를 다시 해.
나는 핵심 원문·기대값과 정상/실패 화면을 직접 대조할게. 테스트 개수나 화면 완성도로 정확성을 주장하지 마.
문서·분석 과제라면 모집단·분모·기간·단위·원자료와 최종 수치, 주장–근거 연결을 먼저 확인해. 과제에 없는 화면·API·알고리즘 검사를 강제하지 마.
