# 마지막 이해 점검 · HTML을 최종 코드에 맞추기

docs/algorithm.html을 최종 구현과 실제 실행 결과에 맞게 갱신해 줘. 없으면 새로 만들어.
notes/spec.md·notes/work.md, 실제 코드·검증 산출물을 읽고 초기 설계와 구현의 차이부터 찾아. 남아 있는 설계 가설을 구현 완료로 바꾸지 마.
입력·설정·목표 순서·seed(해당 시)·코드 함수/버전·재현 명령·실제 실행 시점과 결과 출처를 연결해.
실제 알고리즘의 작은 실행 trace 또는 검증된 결과로 입력→중간 판단→출력→독립 제약 검사→기준 해법 비교를 보여 줘. trace가 없으면 가능한 범위에서 실제 실행으로 확보해. 실행할 수 없으면 설명용 예시/미실행이라고 적어.
원래 코드와 다른 알고리즘으로 애니메이션 결과를 만들지 마. 별도의 시각화 계산이 필요하면 단순화와 차이를 명시해.
정상 예시와 반례/실패 하나, 선택 이유·버린 대안·한계를 넣어. 정원 충족/기준 대비 개선/최적성 주장을 구분해.
실제 코드 변경 후 이 HTML도 다시 맞춰야 함을 적고, 마지막에 내 설명 질문 3개와 해설을 접어서 넣어. 외부 라이브러리 없는 단일 HTML을 유지해.
나는 화면을 닫고 입력→제약→선택→검증→한계를 설명해 보겠다. AI 사용이 금지된 후속 평가가 있다면 그 전에 이 작업을 끝내겠다.
