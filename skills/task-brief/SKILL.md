# 과제 초안

1. 기존 지침·과제 원문·기존 코드·자료·설치/실행 환경을 확인한다. 기존 요구·결정 메모가 있으면 보존하고 현재 유효한 내용을 재사용한다.
2. notes/spec.md 또는 기존 동등 파일에 목표·필수 제출물·입력 계약·제약·성공 기준·미확정과 원문 위치를 짧게 쓴다. 구현 전 임의 가정을 확정으로 쓰지 않는다.
3. 자료만으로 해결되지 않고 답이 결과를 바꾸는 질문을 영향 순서로 제안한다. 각 질문에 달라지는 결정·추천·근거를 붙이고 중요한 2~3개부터 제시한다. 이미 명시된 내용과 단순 구현 세부는 다시 묻지 않는다.
4. 사람에게 결정권이 있는 목표 우선순위는 대안과 영향을 비교한다. 담당자 답이 필요한 업무 사실과 구분한다.
5. notes/work.md에는 현재 상태·답 전 가능한 조사·다음 행동을 적는다. 요구 본문을 복사하지 않는다. 필수 실행 방식의 장애를 초반에 확인한다.
6. 사람은 원문·누락·가정·중요한 결정을 검토한다. 초안과 질문이 준비되었다고 구현 승인까지 받았다고 추정하지 않는다. 이미 구현 범위가 승인되었으면 그 범위는 이어간다.

별도 brief.md를 반복 생성하거나 사람이 requirements.md를 다시 쓰는 단계를 만들지 않는다. HTML로 보고 싶을 때만 kit/preview.py를 사용한다.
