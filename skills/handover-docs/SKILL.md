# 문서 작성

과제 안내가 정한 파일명과 양식이 있으면 그것을 따른다. README.md 가 과제 안내문이면 그 파일을 고치지 않고 다른 이름(예: REPORT.md)을 사용자에게 제안한다. 없을 때의 기본 구성:

1. 결론 먼저: 무엇을 만들었고 핵심 결과가 무엇인지 3줄 이내.
2. 실행 방법(실행할 것이 있을 때): 명령 그대로, 입력 파일과 출력 파일 경로. 없으면 결과물 위치.
3. 판단과 근거: 중요한 결정마다 무엇을, 왜, 어떤 근거(담당자 답변 시각, 자료 파일·행, 계산)로 정했는지. `notes/decisions.md`와 맞아야 한다.
4. 검증 결과: 무엇을 어떤 방법으로 확인했고 실제 결과(수치가 있으면 수치)가 무엇인지. `notes/verification.md`, `verify/last_result.md`와 맞아야 한다.
5. 가정과 한계: 확인하지 못한 것, 틀릴 수 있는 조건, 적용 범위 밖.
6. 남은 일: 다음에 할 검증과 개선.

쓴 뒤 `python3 kit/preview.py`를 실행해 HTML을 만든다. 읽는 사람은 브라우저 미리보기에서 본다.

## 지킬 것
- 문서의 수치·주장은 출력 파일·실행 결과와 같아야 한다. 쓰기 전에 다시 읽어 맞춘다.
- 하지 않은 테스트·검증을 한 것처럼 쓰지 않는다.
- 짧게. 표와 목록을 쓰고, 꾸미는 문장은 뺀다.
