# 최종 결과와 설명 맞추기

1. 과제 지정 파일명·형식을 따른다. README가 과제 원문이면 보존한다. 기존 spec/work와 실제 파일·실행 결과를 다시 대조한다.
2. 무엇을 만들었는지, 실행 방법·입출력·환경, 핵심 결정·대안·근거, 실제 검증 범위, 미확인·한계·남은 일을 짧게 쓴다.
3. 알고리즘 설명 HTML이 있으면 최종 코드·실행 결과와 맞춘다. 없고 이해에 필요하면 algorithm-html 방식을 사용한다. 가상 예시·실제 trace·단순화를 구분한다.
4. 실행하지 않은 환경이나 테스트를 완료로 쓰지 않는다. 설정 파일 작성과 실제 실행은 다른 증거다. 휴리스틱을 최적해라고 부르지 않는다.
5. 필요할 때만 kit/preview.py로 문서를 읽는 HTML을 만든다. 사람이 목표→입력→핵심 판단→출력→검증→한계를 설명할 수 있게 한다.
6. AI 금지 후속 단계가 있다면 문서/HTML 준비는 그 전에 끝낸다. 특정 평가의 문항 수·시간·허용 규칙을 추정하지 않는다.

“html로 전체 정리해줘”는 실제 최종 코드·검증에 근거한 결과 개요 HTML 요청으로 해석한다. 목표→설계→실제 동작→핵심 알고리즘/판단→검증→한계를 정리하고 초기 HTML이 있으면 갱신한다. 없으면 docs/solution.html에 만든다. 과제에 없는 기능이나 실행 결과를 추가하지 않는다.
