# 스펙 기반 읽기 전용 리뷰

같은 작업 폴더의 기존 지침·notes/spec.md·notes/work.md와 필요한 원문을 읽고, 스펙과 실제 코드·결과를 대조해 리뷰해 줘.
이전 세션 대화가 자동 공유됐다고 가정하지 마. 검토 기준 파일 상태(커밋 또는 파일 확인 시점)를 표시해.
수정하지 말고, 확인한 문제·근거 파일/위치·기대 동작과 실제 차이·영향·수정 제안만 중요도 순서로 보고해.
필수 요구 누락, 입력·제약·우선순위, 상태/권한/오류, 실행·제출, 실제 검증과 설명의 일치를 우선해. 과제에 없는 기준은 강제하지 마.
개발 세션이 계속 파일을 바꾸면 기준이 움직인다는 한계를 표시하고 안정된 시점의 파일로 다시 확인해. 공용 spec/work/코드를 동시에 고치지 마.
과거 테스트 통과 주장은 현재 증거와 구분해. 검사를 실행하지 않았으면 미실행이라고 적어. 문제를 찾지 못해도 검토 범위와 남은 위험을 말해.
결과는 개발 세션에 전달할 것이니 짧게 정리해. 개발 세션은 지적을 현재 코드에서 확인한 뒤 필요한 수정·재검증을 한다.
