# 알고리즘을 이해하는 HTML

1. 현재 spec/work·알고리즘 코드·실제 실행 자료를 읽는다. 구현 전이면 설계 가설, 구현 후면 확인한 코드·함수·버전·실행 시점을 표시한다.
2. 외부 라이브러리·CDN 없는 단일 docs/algorithm.html을 만든다. 작은 입력 하나·반례 하나·표/간단한 SVG·이전/다음 단계부터 만든다. 꾸미기를 위해 구현·검증 시간을 쓰지 않는다.
3. ID·단위·시간 기준 → 제약 → 중간 상태 → 후보 탈락 이유 → 목표 비교 → 선택을 보여 준다. 우선순위 변화에 따른 결과 차이를 설명한다. 정적 예시 전환인지 실제 계산인지 표시한다.
4. 실제 코드와 다른 알고리즘을 재구현해서 실행 결과처럼 보여 주지 않는다. 단순화했다면 생략한 조건과 차이를 적는다. 실제 trace가 있으면 재사용하고 없으면 가능한 실제 실행으로 확보한다. 실행 불가 시 미실행을 표시한다.
5. 마지막에는 같은 HTML을 최종 코드·입력·설정·결과·독립 검증에 맞춰 갱신한다. 초기 설계와 다른 점과 알려진 한계를 보여 준다.
6. 유효성·목표 개선·최적성, 탐색 실패·불가능 입증은 구분한다. HTML 자체를 정확성 증거로 삼지 않는다.
7. 내가 답할 질문 3개와 접힌 해설을 넣는다: 왜 이 후보인가 / 무엇을 바꾸면 달라지나 / 무엇을 검증했고 무엇이 미확인인가. 사용자는 정상·반례를 따라가고 화면을 닫은 뒤 설명한다.

기존 HTML이 있으면 새 파일을 계속 늘리지 말고 갱신한다. AI 금지 평가 단계가 있다면 그 전에 생성·갱신한다.

전체 설계 HTML 요청이면 목표·입력·처리 흐름·구성요소·필수 UI/API(해당 시)·규칙·오류·검증 계획을 보여 준다. 기존 설명 HTML이 있으면 재사용하고 없으면 docs/solution.html에 만든다. 최종 요청에서는 계획과 실제 구현·실행 결과의 차이를 확인한다.
